# TrendLab — non-negotiable project instructions

**Read [docs/REQUIREMENTS_ACCEPTANCE.md](docs/REQUIREMENTS_ACCEPTANCE.md) before proposing architecture, collecting data, scoring trends, changing the UI, or declaring a task complete.** This document is the project's durable requirements and acceptance checklist.

- Scope **updated by user on 2026-11-13**: the official Education category on Android and iOS **available in VIETNAM (VN storefront)**, regardless of developer country. Do not silently gather US/global evidence or use foreign ratings to infer VN trends. VN chart-only discovery remains incomplete.
- Continually discover apps seen or available in VN AND refresh VN-evidenced apps. Daily VN charts are supplementary (Top 100 only), not a complete VN census. The imported 331k global catalog is an **unverified candidate pool**, NOT the Vietnam denominator. Spend limited exploration capacity on unknown IDs; prioritize confirmed VN evidence.
- Collection limits are **per cycle**, not lifetime caps. Measure attempts, success, unique apps observed, freshness, backlog, throughput, and realistic revisit latency. A 24-hour refresh is a target to prove, never a default guarantee.
- Preserve immutable VN-scoped and historic raw observations and provenance. Do not delete the database simply to improve scraper throughput. Never mix US/JP and VN signal histories. Android maxInstalls queried in VN is **NOT VN installs**; iOS VN ratings are local. No estimated downloads, missing-as-zero, or cross-platform counter pooling.
- Trend scores are provisional until adequate time series and validation. Expose readiness, uncertainty, and windows; do not market the prototype as validated predictive analytics.
- A high-quality, usable interactive treemap is essential, but UI polish must not conceal missing catalog coverage or weak data. Tile area MUST represent the positive value of the selected metric linearly, without log/sqrt/minimum-floor compression. Raw counter for scale, raw observed change for delta, model output for Breakout/Sustained, ratings/day for velocity. Zero, negative and missing must be distinguished. Never combine Android and iOS source units.
- Server runs unattended via systemd. Installed monitor/discovery services may STILL have --storefronts us,vn,...; update their ExecStart overrides on rollout and test logs for VN only. Avoid duplicate collectors, destructive DB resets and changes that disable backups. Regional not-found errors warrant long per-app backoff, not global rate-limit throttling.
- Before calling a work item complete, report which acceptance criterion passed, which is only partially met, and which remains unsolved.
- User communication and deployment instructions: **Vietnamese**.

Important limitations today: AppGoblin import is not a verified auto-updating VN catalog; VN Top-K discovery misses long-tail and newly published non-charting apps; Android public maxInstalls is not VN download count; source access, provider rate limits and VN trend validity require auditing.
